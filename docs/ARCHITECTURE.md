# Architecture

## Pipeline

`content/guides/*.json` + `data/*.json` -> schema / policy validation -> build -> `dist/` -> restricted Node HTTP server.

`public/logic.js` contains shared pure functions. `public/app.js` progressively enhances server-rendered pages. `src/render.mjs` generates content and navigation. `src/domain.mjs` owns publication and affiliate decisions. `src/project.mjs` reads source and evidence. `src/ledger.mjs` owns report transitions. The server has no write API, checkout, database, analytics endpoint or payment integration.

## Data boundaries

| Input | Authority and limitation |
| --- | --- |
| Manufacturer specification | Exact cited product variant, dated check; not stock or delivery assurance |
| Article JSON | Authored draft, not a personally tested review |
| Evidence file + hash receipt | Project approval record; not a legal certificate or tamper-proof identity proof |
| Affiliate mapping | An approved external URL and account/site mapping; not a guarantee of commission |
| Imported statement events | Programme-reported status; not bank reconciliation |
| Scenario inputs | Explicit assumptions; never operational KPIs |

The renderer escapes content. External product-source URLs require an exact allowlisted host and configured country/path boundary. Approved affiliate URLs require fresh programme/site and product-mapping evidence. Amazon tag and ASIN-form URLs, and Awin account/merchant/deep-link fields, are validated separately. Programmes still decide eligibility.

## Readiness

Preview is the default. Public builds fail without operator identity/contact, approved domain, owner publication, brand/privacy reviews, exact-content editorial receipts and fresh product sources. Monetisation is separately off by default and is refused in preview builds. `/ops/` is omitted from public builds.

Public builds embed an expiry deadline. The included server stops serving expired public content with HTTP 503. The policy currently uses a 30-day source window and 180-day editorial window; these are project choices, not statutory periods. This implementation fails closed rather than silently presenting old evidence as current. A reviewed rebuild is required to restore service.

Build metadata contains only an allowlisted route map, file hashes, expiry and a source snapshot hash. The server loads verified generated bytes into memory, never serves the project root and never exposes build metadata. Hashes detect accidental build changes; a malicious editor able to replace both content and metadata is outside this integrity check's trust boundary.

## Hosting

Local host defaults to loopback. Non-loopback preview requires a sufficiently long secret, with constant-time verification. Basic auth is only suitable behind HTTPS. `/healthz` exposes a minimal status for the host. Use the Node server, not generic static hosting, to retain the preview authentication and expiry controls.

Docker/Railway files are implementation preparations. Their existence is not deployment evidence.
